## Health grade: **B‑ → C+**, held down by *silent* failure modes

The engineering is still genuinely good (traceable fixes, real durability primitives, a fast isolated test suite). But this pass found that the two things the July‑1 audit certified as **strengths** — the ledger's evidence/injection gate and the index's "never serves wrong text" swap — are both bypassable, and that the entire nightly pipeline is quietly defeating its own recency and incremental‑rebuild logic. The recurring shape is the same one that dominated July‑1: **the system reports success while silently doing the wrong thing (or nothing).** None of this is loud; all of it is corrosive to a knowledge base you trust an agent to read from.

## Four corrections to the July‑1 audit (read these first)

These change conclusions that audit drew, so they take precedence over the new findings below.

- **C1 — The ledger's evidence gate + `NOTE_FENCE` is *not* the working injection defense it was cited as.** July‑1 listed "Defended agentic write path … gates every check‑off behind `filter_completions_by_evidence`" and the fence as verified strengths. This pass reproduced three independent bypasses (see **M‑M**): the evidence quote is not bound to the item being completed, the check is satisfied by the tool's *own* injected fence/header boilerplate, and machine‑extracted ledger item text is re‑injected into the prompt **unfenced** every night. The gate is better than nothing but does not hold the line it was credited with.

- **C2 — The index swap is a *two‑file* swap with a *count‑only* guard, not an "atomic single‑file swap [that] never yields wrong text."** July‑1 line 21 overstates it. `build_index` writes two tmp files and does two separate `os.replace`s with **no `fsync`** (the note‑write path in `safe_paths` is strictly more durable), and the searcher's only consistency check is `index.ntotal == len(chunks)` — a row *count*. A crash between the two replaces, or a cross‑process reader straddling them (`INDEX_LOCK` is in‑process only), can pair FAISS row *i* with a different `chunks[i]` while counts still match → **correct‑looking results under the wrong note path** (see **M‑K / low‑1**).

- **C3 — "Incremental rebuild / only changed notes re‑embed" (docs) is false; the nightly build re‑embeds the *entire* vault.** `build_index(force=False)` is binary: signature match → skip everything; any file changed → re‑embed **every chunk of every note**. There is no per‑chunk cache. Because daily notes + hourly reMarkable OCR flip the signature every day — and because the nightly linker itself rewrites every note (see **H‑B**) — the "incremental" path never engages in practice.

- **C4 — The oversized‑chunk risk is silent *truncation* (data loss from retrieval), not a build abort.** One lane rated this HIGH on the theory that an over‑length embedding request aborts the whole build. **I tested the live endpoint** (`192.168.0.29:1234`, nomic‑embed‑v2‑moe): a 300 000‑char single input returns a normal 768‑dim vector with **no error** — it truncates. So the correct severity is medium: the tail of any oversized chunk is silently dropped from the index (**M‑B**), not a frozen pipeline. (The vectors also come back **L2‑normalized** — norm = 1.000 — so `IndexFlatL2` ranking is monotonic with cosine; only the *cross‑query* score scale is off, as noted in low‑5.)

## HIGH

### H‑A — Nightly linker crashes on a backslash in any model‑generated summary (`re.sub` replacement‑string injection)
**`moc_linker.py:259` (`upsert_managed_block`), `:375` (`upsert_related_block`), `:320` (`tag_notes`).**
All three replace a managed block via `pattern.sub(block, existing)`, where `block` embeds the model‑produced `desc` and note titles. In `re.sub` the **second argument is a replacement template** — backslashes and `\1`/`\g<…>` group refs are interpreted. **Reproduced by hand on this tree:** a desc of `see \1 backup` or a Windows path `C:\temp\1` raises `re.PatternError: invalid group reference`; a desc with `\n`/`\t` silently injects real newlines/tabs into the MOC file. `write_mocs` has **no try/except** around the per‑MOC loop, so one bad desc aborts the whole linker run — every later MOC (sorted order) **and** the entire `tag_notes` + `cross_link` pass never execute. Realistic in a dev/knowledge vault (paths, LaTeX, regex, code snippets end up in summaries).
**Fix:** use a function replacement — `pattern.sub(lambda _m: block, existing)` — which is inserted verbatim with no escape interpretation. Same at the `tag_notes` `re.sub(r"^moc:.*$", …)` site. Wrap the per‑MOC loop in try/except so one note can't kill the run.

### H‑B — The nightly "mtime‑churn cascade": every note is rewritten every night, defeating three separate systems
**`moc_linker.py:301,329,413` (unconditional `path.write_text`), `:244,363` (minute‑resolution timestamp in every managed block), `mcp_server.py:300-309` (linker‑then‑ledger order).**
`tag_notes` and `cross_link` call `write_text` on essentially every note **with no `new_text == original` guard**, and each managed block stamps `*Updated {now:%H:%M}*`, so the content differs every run anyway. Consequences, all silent, all nightly:
1. **Defeats the ledger's core premise.** `ledger_update.gather_recent_notes` keeps notes with `mtime >= now − recent_days`. The linker runs *first* and touches every file, so seconds later the ledger sees the **entire vault** as "recently edited" and reconciles an arbitrary post‑linker slice (further capped at 16 000 chars) instead of the notes you actually edited. The "look at what the human changed" contract is inert in the real deployment.
2. **Forces a full nightly re‑embed** (this is the mechanism behind C3): every mtime bumps → `vault_signature` always changes → whole‑vault re‑embed every night.
3. **Collateral:** universal‑newline translation silently normalizes CRLF→LF on every note; the un‑timestamped `{stem}.bak.md` backup is overwritten within 24 h, so any corruption is unrecoverable next day.
**Fix:** make `tag_notes`/`cross_link` skip the write when `new_text == original`, and drop the minute‑level timestamp (or make the block content‑derived) so idempotent nights don't touch files. Independently, run the ledger *before* the linker, or capture mtimes before the linker runs.

## MEDIUM

### Retrieval quality (the largest cluster — all silent degradation)

- **M‑A — Embeddings omit the nomic‑required task prefixes.** `text-embedding-nomic-embed-text-v2-moe` is trained to receive `search_document: ` before every indexed passage and `search_query: ` before every query (verified against the model card, 3/3 verifiers). The code sends raw text on both sides (`indexer.py:202`, `searcher.py:55`), and LM Studio/llama.cpp does **not** inject them. This discards the query‑vs‑document asymmetry the model was tuned for — a systematic, every‑query ranking loss. **Fix:** prepend the prefixes on both sides; land together with one `--force` reindex (a query prefix against unprefixed documents is worse than neither).
- **M‑B — Oversized chunks are silently truncated at the 512‑token window.** `chunk_text` only splits on `.!?`‑boundaries and never sub‑divides a single over‑long "sentence" (`indexer.py:112-114`); a punctuation‑free run (transcript, table, bullet/link list, pasted code, OCR) becomes one chunk far past 512 tokens, and the endpoint truncates the tail out of the index (see C4). **Fix:** hard‑split any single sentence exceeding the budget on a word boundary; cap chunk chars.
- **M‑C — A note's title/filename never reaches its embeddings.** `scan_vault` embeds only the body and strips frontmatter (`indexer.py:136-139`), yet in Obsidian the *filename* is the title and is often the only place a person/project name appears (`Rekow 1-1 2026-06-30.md` whose body never repeats "Rekow"). Queries naming that entity retrieve the note poorly — the exact "ask about a person" path the brain exists for. **Fix:** prepend the filename stem (+ frontmatter aliases) to the text before chunking.
- **M‑D — Entity notes are write‑only and can never be retrieved.** `brain_write_entity` writes `_brain/entities/<slug>.md`, but `scan_vault` skips any path containing `_brain` (`indexer.py:130`), and there is no second index — so the curated people/project notes are structurally invisible to `brain_query`. The `_brain` skip (meant to avoid re‑indexing the FAISS files) overshot and now hides first‑class knowledge. **Fix:** index `_brain/entities/*.md` while still excluding the index/derivative files.
- **M‑E — The linker's `## Related Notes` block is re‑embedded into its own note — a precision feedback loop.** `cross_link` writes wikilink boilerplate into every body; `scan_vault` strips only frontmatter, so next build the heading, every linked *title*, and the desc text get embedded as ordinary content. Note A then retrieves for topic X merely because it *links* to a note about X — a self‑reinforcing quality drift (linker output → index → linker re‑reads). **Fix:** strip managed blocks/HTML comments in `scan_vault` before chunking.
- **M‑F — The embedder trusts the endpoint's response order and never sorts by `.index`.** `_embed_one_batch` returns `[item.embedding for item in response.data]` (`embedder.py:44`); the OpenAI embeddings API does not guarantee order (the per‑item `index` field exists precisely to reorder), and the installed SDK does not reorder for you. A single out‑of‑order batch mis‑pairs up to 63 of 64 chunks' text with another chunk's vector — the count guard still passes, so it's invisible. **Fix:** one line — `sorted(response.data, key=lambda d: d.index)`. Zero migration cost.

### Task tool
- **M‑G — The task scanner and completer are code‑fence‑blind.** `TASK_RE` matches every raw line with no ```/~~~ fence tracking. **Reproduced end‑to‑end:** a `- [ ]` inside a fenced *documentation example* is listed as an open task, and `brain_complete_task` will rewrite that line **inside the code block** to `- [x] … ✅ <date>`, corrupting the example. This is on the one tool whose entire value proposition over semantic search is exactness. **Fix:** track fence state in both `scan_tasks` and `complete_task` via one shared fence‑aware iterator.

### Maintenance write‑path corruption
- **M‑H — `tag_notes` hand‑rolled frontmatter editing corrupts notes.** **Reproduced against temp files:** a block/list‑form `moc:` value (`moc:\n  - "[[Old]]"`) becomes invalid YAML after the `^moc:.*$` substitution leaves the orphaned list item; and a note that *opens* with a `---` thematic break trips `startswith("---")` and hoists the leading heading + body into frontmatter. Obsidian then drops the whole property block or the body vanishes from the render. Zero test coverage. **Fix:** parse/re‑emit frontmatter as real YAML; only treat a leading `---` as frontmatter when a proper close fence precedes the first blank line.
- **M‑I — `moc_linker.extract_json` can't parse any object containing a brace** (`re.findall(r"\{[^{}]*\}")`, `:162`). **Reproduced:** a valid `{"moc":"Code","desc":"python dict {k: v} example"}` returns `None`; the note falls back to `Unsorted` permanently, and `temperature=0` makes it deterministic. This is a *different, more fragile* parser than `ledger.find_json_object` (July‑1 H‑2), so the JSON‑no‑op class regresses here independently. **Fix:** reuse a balanced‑scan/`json.loads`‑slice approach; add a braced‑desc test.
- **M‑J — `write_mocs` never prunes an emptied MOC.** It only rewrites MOCs that received ≥1 note *this* run, so a reclassified note stays listed in its **old** MOC while also appearing in the new one — dangling, contradictory links. Mass‑triggered by commit `466d3b1`, which swaps the linker onto a weaker model that re‑classifies everything on its first run. **Fix:** regenerate every discovered MOC's block each run (empty block for MOCs that got zero notes).

### Index integrity
- **M‑K — A corrupt/torn index is never self‑healed; every query then silently returns "No relevant notes found" forever.** The incremental fast‑path returns `already_current` after a `vault_signature` match **without ever opening `index.faiss`** (`indexer.py:164-180`). If the index file is corrupt/truncated but metadata is intact and the vault is unchanged (a torn LiveSync replication of `_brain/`, or a crash between the two replaces), the searcher's guard returns `[]` and **no rebuild path fires** (both nightly and `brain_build_index` default `force=False`). The agent reads "nothing matched" and never rebuilds — a permanent, silent retrieval outage. Sharpens July‑1 M‑1 (which only guards `brain_status`'s read). **Fix:** on the incremental path, cheaply `faiss.read_index` + assert `ntotal == len(chunks)`; fall through to a full rebuild on any failure.
- **M‑L — The freshness key ignores the embedding model and chunk params.** `_vault_signature` hashes only `(relpath, mtime)`. Swapping `EMBEDDING_MODEL` to another 768‑dim model, or changing `CHUNK_SIZE`/`CHUNK_OVERLAP`, without `--force` leaves the stale index in place while queries embed with the new model → mismatched vector spaces, silently degraded results and no rebuild. Sharpens July‑1 M‑3 (whose searcher‑side fix would then return empty **forever** because the build side still won't rebuild). **Fix:** fold `EMBEDDING_MODEL` + chunk params into the freshness decision.

### Ledger safety (the C1 corrections, consolidated)
- **M‑M — The ledger's evidence/injection gate is weaker than certified, three ways.** `filter_completions_by_evidence` keeps a completion iff its ≥15‑char evidence quote is a substring of the concatenated recent‑notes context. **All reproduced:** (1) **not item‑bound** — the quote need only appear *somewhere* in the blob, not near the item `n` the model chose, so a real quote can check off the *wrong* open item; (2) **satisfied by the tool's own boilerplate** — the constant fence string `-----8<----- UNTRUSTED NOTE BODY …` and the `file: <rel>` header are always present, so evidence = that framing text passes the gate; (3) **unfenced re‑injection** — machine‑extracted `new_items[].text` is written into the ledger and read back into the prompt's OPEN/TRACKED sections **without** the fence every night, a durable injection foothold. A single poisoned transcript can flip a genuinely‑open action item to `- [x] … ✅`. **Fix:** validate evidence against the raw per‑note bodies (strip fence/headers); bind the quote to the item's own text; fence the tracked/numbered sections too.

### Security
- **M‑N — DNS‑rebinding / Origin+Host validation is silently disabled because the server binds `0.0.0.0`.** The MCP SDK only auto‑enables `TransportSecuritySettings` when the bind host is loopback; with `MCP_HOST=0.0.0.0` that branch is skipped and `security_settings` stays `None`. So even *with* a bearer token, a malicious web page the user merely visits can DNS‑rebind to `http://<host>:8053/mcp` as same‑origin and bypass browser CORS to read/write the vault. A distinct control from July‑1 H‑1's missing token. **Fix:** bind `127.0.0.1` behind a proxy (auto‑re‑enables the allowlist) or pass explicit `TransportSecuritySettings`.

### Ops
- **M‑O — An out‑of‑range `BRAIN_REFRESH_AT_HOUR` boots "healthy" then kills the scheduler on the first loop.** `hour = int(os.environ.get("BRAIN_REFRESH_AT_HOUR","3"))` has no range check; `int("24")` succeeds, the container serves, `/health` returns 200, then `_seconds_until_hour` calls `datetime.now().replace(hour=24)` → `ValueError`, uncaught, and the daemon thread dies. No watchdog → the nightly index refresh + linker + ledger never run again for the container's life while `/health` stays green and `restart: unless-stopped` never fires. Sharpens July‑1 M‑6/L‑6. **Fix:** clamp to 0–23 with a logged fallback, and wrap the `_refresh_loop` body in its own try/except.

## LOW / notable (verified, lower blast radius)

1. **Index swap not `fsync`'d + count‑only guard + cross‑process race** can serve wrong text/paths (the C2 mechanism). `indexer.py:223-229`, `searcher.py:49`.
2. **`cleanup_tmp_files()` runs outside `_build_lock`** (`indexer.py:160`) — two concurrent builds can delete each other's in‑flight `*.tmp` mid‑swap.
3. **`consolidate.py --force` is dead code** — `brain.consolidate()` always `force=True`; the no‑flag cron invocation prints `force=False` while doing a full re‑embed.
4. **`_slugify` collisions silently drop a second entity's content** (`John Smith (client)`, `John Smith - client`, `John Smith, client` all → one file; second write returns `exists` and discards its content); a non‑ASCII name collapses to a bare `.md` dotfile.
5. **Dedup can return < top_k, no relevance floor, non‑comparable scores.** `search` fetches only `2·top_k` then dedupes to one chunk/note (can under‑fill top_k when one big note dominates), never applies a distance cutoff (out‑of‑domain queries still get 5 "results"), and reports `1/(1+dist)` over *squared* L2 (not comparable across queries — though vectors are normalized, so within‑query ranking is sound).
6. **Ledger dedup normalizes the key but not the haystack** — an item with `/`, `-`, etc. in its first 40 chars evades the deterministic backstop and is re‑appended nightly.
7. **`upsert_*_block` replace‑all** destroys user content that merely quotes the markers, and duplicates the block if a LiveSync merge left two marker pairs.
8. **Auth middleware returns 500, not 401, on a non‑ASCII `Authorization` header** (unhandled `TypeError`).
9. **`top_k` and query size are unvalidated** into `faiss…search` (negative/huge values flow through).
10. **Cleartext note content over LAN** to the embed + nightly chat endpoints; the new `LINKER_CHAT_URL`/`LEDGER_CHAT_URL` (added in `466d3b1`) get no scheme/host validation or logging.
11. **Unpinned deps** (`mcp>=1.26.0`, no upper bounds, no lockfile) baked into a cached pip layer → a rebuild on a fresh host/after a cache prune can silently install an incompatible set and break the only container.
12. **DST fall‑back** fires the nightly refresh an hour off (naive `datetime` arithmetic).
13. **Doc drift:** README omits `LEDGER_CHAT_URL`/`LEDGER_CHAT_MODEL`; `RESUME.md` is stale (external cron, cosine re‑rank that never shipped); `SKILL.md` claims an embedding outage yields empty results when the code actually raises; `CLAUDE.md` and `SKILL.md` both declare the skill name `obsidian-brain` and have drifted.
14. **`.dockerignore` omits `.venv/`** → the whole virtualenv is uploaded as build context every build.

## Scalability & recovery gaps (no performance dimension existed in either audit)

- **No true incremental re‑embed** (root cause behind C3 / H‑B): the fix is a per‑chunk **content‑hash → vector cache** so only changed chunks hit the endpoint. This is the enabling primitive for near‑real‑time refresh.
- **Every query re‑reads the whole index from disk** (`faiss.read_index` + `json.loads` of the full `metadata.json`, which stores every chunk's text) — latency and memory grow linearly with the vault, and stateless‑HTTP re‑pays it on **every** request. An in‑process cached index (invalidated on rebuild) is the fix.
- **`IndexFlatL2` is brute‑force O(n·d)** — fine now, degrades at thousands of notes; ANN (IVF/HNSW) later.
- **No restore path exists and backups grow unbounded.** Maintenance scripts write pre‑edit backups but there is no restore tool, no validation that a backup is restorable, and timestamped MOC backups accumulate until they fill the host disk. A backup you've never restored from is a hypothesis, not a safety net.

## Feature recommendations

You named three: a UI, an Obsidian plugin, and a way to stop conflicting/incorrect transcript notes from compounding. All three are feasible on this codebase; the third is the most valuable and the most novel. **One caveat the design‑critic surfaced and it's load‑bearing:** the UI and plugin both need the *same* small REST surface and both touch the *same* auth story, so design the HTTP contract **once**; and the truth‑maintenance and "frontmatter‑aware indexing" work both rewrite the *same* `scan_vault`/`build_index`/`search` seam — do them as one project, not two.

### 1. Truth maintenance — stop transcript errors from compounding *(the headline ask; staged S→M→L→M, XL in full)*

The failure you're describing is a **closed compounding loop**, and today every link in it is unguarded: a transcript/OCR note lands with no provenance → the index treats it at equal authority (frontmatter is stripped) → the nightly linker amplifies it (Related links + a tracked action item) → the searcher serves it with no "contested" flag → an agent writes a *new* note citing it → two notes now corroborate the error → it becomes load‑bearing.

The design cuts specific links with layers, reusing the patterns you already proved in `ledger_update.py` (local chat model via `_post_json`, dry‑run default, managed `<!-- -->` blocks, backups outside the vault, evidence gating, `NOTE_FENCE`). **Governing principle: the local model is a triage sensor, never a judge** — it decides "these two notes deserve 20 human‑seconds," never "this note is wrong." Verdict authority lives in a human review queue.

- **Layer 1 — Provenance frontmatter** (`source_type`, `ingested`, `review_status`, `confidence`, `superseded_by`, `contested_by`). A nightly backfill stamps unstamped notes heuristically by path/shape. *Cuts nothing alone; enables the rest.*
- **Layer 2 — Nightly contradiction detection** (new `truth_maintenance.py`, sibling of `ledger_update.py`): extract atomic claims from recently‑changed notes → retrieve semantic neighbors → per‑pair NLI judgment → **precision gating** (both‑side evidence must be a substring of both source notes, a same‑subject cosine floor, sibling suppression). Honest about local‑model reliability: NLI is hard for a sub‑70B model, so the design is **precision‑biased** — a false positive costs 20 seconds of dismissal, never a wrong auto‑edit. *Cuts amplify→serve.*
- **Layer 3 — Review‑queue note** (ledger‑style managed block): conflicts land here for human adjudication, not auto‑fix. *The circuit breaker; cuts the auto‑fix loop.*
- **Layer 4 — Supersede/contested semantics in retrieval:** `build_index` projects `review_status`/`superseded_by` into chunk metadata; `search` down‑weights (×0.4 superseded, ×0.7 contested, ×0.6 unreviewed) but **never drops**; `format_results` annotates each hit `⚠️ SUPERSEDED → [[Correct Note]]`. **This annotation is the load‑bearing fix** — the agent that compounds errors is the one that must *see* the flag. *Cuts serve→corroborate.*
- **Layer 5 — Soft quarantine:** fresh unreviewed transcript/OCR stays searchable (down‑weighted, flagged) but is excluded from linker/ledger amplification until reviewed. Hard quarantine rejected (OCR is often the only record).

Layer 4 **is** capability roadmap #8 (frontmatter‑aware indexing) — build them together. Rollout is observe‑only first: ship Layer 1 + Layer 4 down‑weighting, run Layer 2 writing only to the queue while you grade its precision, and enable automated `contested`/`superseded` writes only once you trust the sensor. Reuse the M‑4 loud‑failure‑count pattern so an "endpoint down → no conflicts" night is distinguishable from a genuinely clean one. **Fix M‑9 (the linker's unfenced prompt) in passing**, since this module ingests two untrusted notes per judgment.

### 2. Web UI — pages baked into the existing Starlette app *(effort M)*

Serve one self‑contained page (`GET /ui`, inline CSS/JS, no build step, no new container) plus thin JSON routes on the app `mcp.streamable_http_app()` already returns. Panels: **ask/search** (score + note path + snippet, `obsidian://open` deep‑links), **open tasks**, **status/ops** (vault, model, index counts, last‑refresh time, **last nightly linker/ledger exit code + timestamp** — this is also roadmap #4/the morning digest), and a **guarded append‑insight** form. The browser auth story is the crux and it's clean: add only the HTML shell to the middleware's public paths; the page reads a token from `sessionStorage` and every data call is a same‑origin `fetch('/ui/api/…', {Authorization: 'Bearer …'})` through the **exact same `compare_digest` gate** as `/mcp` — no new auth code. **Must‑nots:** when `BRAIN_AUTH_TOKEN` is unset, the write route refuses (503) rather than opening an anonymous write path (the direct lesson of H‑1); render note text with `textContent` never `innerHTML`; same‑origin only. **One real implementation note:** custom routes run on the uvicorn event loop *without* the threadpool isolation MCP tools get, and every `search`/`tasks` call is blocking (an HTTP embed of seconds) — wrap them in `run_in_threadpool` or a single search stalls the whole server, `/mcp` included.

### 3. Obsidian plugin — the active‑note lens *(effort M)*

Build it **only if it leans into the one thing a browser tab can't do: query the brain using the active note as live context.** A live **related‑notes side panel** (re‑queries on note switch against current, even unsaved text — complements the linker's static nightly `## Related Notes` block rather than duplicating it), an **"ask the brain" command** that inserts a `[[link]]` at the cursor, and a settings tab for the URL/token. Verified against Obsidian docs: use `requestUrl` (CORS‑free, works on desktop **and** mobile, so `isDesktopOnly: false`), `ItemView` in the right leaf, `active-leaf-change` (debounced) for live updates, `loadData/saveData` for the token, ship via BRAT. Talk **plain REST**, not MCP/SSE (fragile over `requestUrl`). **Risks:** the token lands in plaintext `data.json` that LiveSync replicates to every device — use a dedicated token, land H‑1, prefer HTTPS/VPN off‑LAN. A save‑hook auto‑refresh is **deferred** — it needs a `POST /refresh` endpoint that doesn't exist yet *and* the incremental embedding cache (else every save re‑embeds the vault).

### Cross‑cutting design decisions (from the design critic)

- **Define the REST contract once.** Both #2 and #3 need `/ask` (or `/ui/api/search`) and `/refresh`; the lanes independently specified *incompatible* shapes (one over the string‑returning `query_brain`, one over structured `searcher.search`). Pick the structured shape (`searcher.search` returns `{note_path, abs_path, score, text}`); `query_brain` returns a preformatted markdown string, not data. One owner for `/refresh` (it *is* roadmap #3).
- **When the token is unset, *every* new route is public** (the middleware installs only when the token is set — today's live state). Every design above must fail closed on writes in that mode.
- **Nightly GPU contention.** Truth‑maintenance and a would‑be entity‑extractor stack on the existing linker+ledger, all on one local model. Sequence them; don't run four unattended LLM writers concurrently.
- **The remote‑access story collides with H‑1's fix.** H‑1 wants a loopback bind; the UI's "ask from my phone" and the plugin's mobile path then both require the *same* reverse‑proxy/VPN prerequisite. Decide that once (SSH‑forward vs SWAG/Authelia vs Tailscale) before building either.

### Re‑ranked capability roadmap (beyond the three above)

1. **Full‑note & structured read tools** (`brain_get_note`, `brain_recent_notes`, `brain_backlinks`) — **S**, best ratio; the current 500‑char chunk snippets shred 60–99 KB transcripts.
2. **Per‑chunk embedding cache** (content‑hash → vector) — **M**; fixes C3/H‑B's full nightly re‑embed and is the prerequisite for #3.
3. **`POST /refresh` + optional watchdog** — **M**; kills the up‑to‑24 h unsearchable window. *Sequence after #2.*
4. **Retrieval eval harness** (20–40 `query→expected‑note` golden pairs, recall@k/MRR) — **S–M**; every quality bet below claims to "improve retrieval" with no way to measure regressions. Do it before the bets it protects.
5. **Hybrid BM25 + vector** — **M**; the vault is dense with exact proper nouns/codes ("PJM", "Rekow") that pure vectors blur. Prefer `bm25s` (numpy‑backed, persistable).
6. **Local‑model reranker** — **M**, opt‑in (adds LLM latency to the query path); reuses `moc_linker._post_json`.
7. **Nightly entity extraction** — **M**, but **gated** behind the maintenance‑write hardening (H‑A, M‑9, atomic writes): it's a third unattended LLM *writer* on a subsystem with open silent‑failure findings. Consider instead making the *interactive* agent write entities reliably.
8. **Frontmatter‑aware indexing + filters** — **L**; the single biggest retrieval lever ("decisions about PJM from June"), and **the same seam as truth‑maintenance Layer 4** — build them together. Needs PyYAML + a reindex.
9. **Morning digest** — **S**; build on the M‑4/M‑7/M‑8 observability fixes (same failure‑count data).
10. **claude‑mem bridge** — **M**; make the vault the single source of truth the README claims.
