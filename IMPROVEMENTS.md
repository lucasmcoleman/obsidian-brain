# Obsidian Brain — Usability & Functionality Improvement Menu

> A menu of options for maintainer review. Nothing here is implemented yet. Items are grouped by payoff tier and ordered for impact within each tier. Effort is rough: **S** = hours, **M** = a day or two, **L** = multi-day. Each item is grounded in the current codebase (`config.py`, `embedder.py`, `indexer.py`, `searcher.py`, `brain.py`, `tasks.py`, `mcp_server.py`, `moc_linker.py`, `ledger_update.py`).

---

## Quick wins

| # | Title | What it is | Why it helps (user value) | Effort | Risk / trade-offs |
|---|-------|-----------|---------------------------|--------|-------------------|
| Q1 | **Return resolvable note links in `brain_query` results** | `format_results` currently prints `note_path` as plain text. Emit the title as an Obsidian `[[wikilink]]` (or `obsidian://` URI) plus the vault-relative path so an agent/user can jump straight to the source note. | Turns retrieval output from "here's some text" into navigable references; the agent can cite notes the user can click. Closes the loop between search and the vault. | S | Wikilink resolution depends on Obsidian's link settings; include both the link and the raw path to be safe. |
| Q2 | **Add a score threshold + "why this matched" to results** | Drop results below a configurable `MIN_SCORE`, and surface the numeric score (already computed as `1/(1+L2)`) with a one-line label like "weak match". | Stops the agent from confidently reasoning over near-random low-similarity chunks; gives a signal that retrieval found nothing solid (vs. "No relevant notes found"). | S | Score is L2-derived, not cosine, so the threshold needs empirical calibration; expose it as config, don't hardcode. |
| Q3 | **`last_refresh` / health detail in `brain_status`** | Add fields: last successful build timestamp, last build duration, last build status, scheduler enabled/next-run hour, embedding-endpoint reachability (a cheap ping), and `index.ntotal == len(chunks)` consistency flag. | Makes the one "is my brain healthy?" tool actually answer the question. Operator can tell stale-but-running from broken without grepping `docker logs`. | S | Endpoint ping adds latency to status calls; make it best-effort with a short timeout. |
| Q4 | **Explicit `timeout`/`max_retries` on the embedding client** | Pass `timeout=~30s, max_retries=1` to the `OpenAI` client in `get_client()` instead of the SDK's 600s/2 default. | Interactive `brain_query` fails fast and legibly when LM Studio stalls (model loading, GPU stuck) instead of hanging up to 10 minutes. | S | Too-low a timeout could clip a legitimately slow first embed after model load; make it configurable. |
| Q5 | **Distinguish "no index built" from "no matches"** | When `index.faiss`/`metadata.json` are absent, return a distinct status/message ("brain not built — run brain_build_index") rather than the same `"No relevant notes found."` as a healthy-but-empty search. | The agent learns to self-heal (trigger a build) instead of telling the user "nothing found" when the brain simply doesn't exist yet. | S | Minor: requires a small return-shape change consumers must tolerate. |
| Q6 | **Standardize tool return contract (status JSON everywhere)** | Make `brain_query`, `brain_write_entity`, `brain_append_insight` return structured JSON with an explicit `status` field, matching `brain_complete_task`/`brain_build_index`. Today success/failure of `append_insight` are both prose strings ending in the same path. | An agent can deterministically tell "I recorded that" from "I silently failed" instead of regex-matching English. Prevents false "I saved it" claims to the user. | S | Changing return shapes is a (small) breaking change for any existing prompt that pattern-matches the old strings. |
| Q7 | **Remove dead `cosine_sim` + fix docs to match reality** | Either delete `searcher.cosine_sim` (never called) and correct README/CLAUDE.md/comments that claim a "cosine re-rank" step, or wire it in (see H1). At minimum, stop the docs from overstating retrieval. | Eliminates a misleading docs-vs-code gap so future contributors trust the code. Removes a dead-code landmine. | S | None if just removing/correcting; pairs naturally with H1 if you instead choose to implement it. |
| Q8 | **`*.tmp` startup cleanup + index/metadata consistency guard** | On startup (or before each build), delete leftover `index.faiss.tmp`/`metadata.json.tmp`; in `search()` assert `index.ntotal == len(chunks)` and return `[]`/"stale index" rather than letting `chunks[idx]` raise `IndexError`. | Turns a crash-mid-swap or model-dimension-change from an opaque tool exception into a graceful "rebuild needed". Cheap resilience for the atomic-swap edge cases. | S | The consistency check is a guard, not a true fix for the two-`os.replace` non-atomicity (see H4). |
| Q9 | **Vault-containment guard on `note_path` (security, low-effort version)** | In `append_insight` and `complete_task`, resolve the path and reject anything outside `VAULT_PATH` (`Path.resolve()` + `is_relative_to`), reject absolute/`..` escapes, restrict to `*.md`. | Closes the path-traversal write primitive that currently lets any caller append/modify files outside the vault. High-value safety fix that's only a few lines. | S | Could break a legitimate workflow that writes via absolute paths; treat absolute-in-vault paths as allowed, only block escapes. |
| Q10 | **Narrow + log swallowed exceptions in `scan_vault`** | Replace bare `except Exception: continue` with `except (OSError, UnicodeDecodeError)` + a stderr log of the path, and read with `errors="replace"`. | "Why can't the brain find note X" becomes debuggable; encoding hiccups degrade a note instead of silently dropping it from the index. | S | Slightly noisier logs; intended. |

## High-value

| # | Title | What it is | Why it helps (user value) | Effort | Risk / trade-offs |
|---|-------|-----------|---------------------------|--------|-------------------|
| H1 | **Actually wire cosine re-rank (or switch to cosine index)** | Store chunk embeddings (or normalize at index time and use `IndexFlatIP`), then re-rank FAISS candidates by true cosine before dedup — delivering the ranking the docs already promise. | Better top-k relevance, especially for the long/short-note mix; scores become comparable across queries. Fixes the single biggest retrieval-quality gap. | M | Storing vectors grows `metadata.json` / adds a sidecar; or migrate to normalized `IndexFlatIP` (cleaner). Requires a one-time full rebuild. |
| H2 | **Hybrid keyword + semantic search (with MMR diversity)** | Add a lexical pass (BM25 / simple TF-IDF over chunks) fused with the vector scores, plus Maximal Marginal Relevance to avoid returning three chunks of the same note/topic. | Catches exact-term queries (names, IDs, project codes) that pure embeddings miss, and broadens coverage so `top_k` actually yields diverse distinct notes. Big real-world precision/recall lift. | L | More moving parts; fusion weighting needs tuning. MMR alone is a smaller, S/M down-payment if BM25 is too much. |
| H3 | **Delete-aware & content-aware incremental indexing** | Track the set of indexed files (count + sorted-path hash, and/or per-file content hash) in metadata; rebuild when the set changes, not just when `max(mtime)` advances. Optionally per-note incremental embed instead of full re-embed. | Deleted/renamed notes stop surfacing as ghost results with broken paths. Per-note incremental makes nightly refresh dramatically cheaper and avoids re-embedding the whole vault every run. | M | Per-note incremental adds index-mutation complexity (FAISS row management); the metadata-set check alone is the M-effort core that fixes the correctness bug. |
| H4 | **Single-unit atomic index swap** | Write `index.faiss` + `metadata.json` into a per-build dir (e.g. `_brain/index-<ts>/`) and flip one `current` pointer/symlink the searcher follows, so a crash can never pair a new index with old metadata. Add a cross-process lock (`fcntl`/`filelock`) or per-process unique tmp names around the build. | Eliminates the "new index + stale metadata → wrong note returned / IndexError" failure and the two-builders-clobber-tmp race. Hardens the core durability story for crashes and out-of-process refreshes. | M | Symlink/pointer indirection is a structural change to read paths; needs careful migration and search-side update. |
| H5 | **Batched + retrying embeddings with partial-progress** | Chunk `embed_texts` into fixed-size sub-batches (e.g. 64) with bounded retry/backoff per batch; on failure, either fail only if zero batches succeed or write a smaller valid index and log skipped count. (The legacy `obsidian_brain.py` already did this with `--batch`.) | A single LM Studio hiccup or a vault that outgrows the server's max batch no longer aborts the entire nightly build. Scales with vault growth instead of breaking at a threshold. | M | Slightly more code; batch size needs a sane default + config. Re-introduces behavior that was dropped in the rewrite. |
| H6 | **Authentication for the HTTP transport** | Add bearer-token (shared secret) middleware to the streamable-HTTP app; reject unauthenticated tool calls (keep `/health` open). Default-bind to `127.0.0.1` unless a token is configured, and document the SSH-forward pattern as the no-auth fallback. | Currently anyone reaching `host:8053` can read and *write* the entire personal vault unauthenticated. This is the top security gap; auth contains read, write, and the expensive `brain_build_index` DoS in one move. | M | Token management/rotation is operational overhead; must update the remote client registration. Pair with Q9 for defense-in-depth. |
| H7 | **Config file + CLI flags, not just `OBSIDIAN_VAULT_PATH`** | Make `LM_BASE_URL`, `EMBEDDING_MODEL`, `CHUNK_SIZE/OVERLAP`, `TOP_K`, `MIN_SCORE`, timeouts, batch size honor env **and** a config file (TOML/YAML) and/or CLI flags. Today only the vault path is env-driven — the docs that say LM Studio is configurable are inaccurate for the core path. | Lets users point at a different model/endpoint, tune chunking, or run a second vault without editing source. Removes the config-drift footgun where the env var only affects the maintenance subprocesses. | M | Need a clear precedence order (CLI > env > file > default) and to keep backward compatibility with the current single env var. |
| H8 | **New read tools: `brain_get_note`, `brain_list_entities`, `brain_recent_notes`, `brain_backlinks`** | Round out the tool surface: fetch a full note by path/title; list entity notes under `_brain/entities/`; list notes by recency (mtime); resolve `[[wikilink]]` backlinks for a note. | Retrieval gives snippets; agents frequently need the *whole* note, the list of known entities, "what changed lately", or who-links-to-what. These are common asks the current 7 tools can't serve. | M | More tool surface = more to secure (apply Q9 guard) and document; backlinks need a link-scan pass (cheap to compute on demand or cache). |
| H9 | **Observability: structured logs + metrics + a maintenance-status surface** | Emit structured (JSON) log lines for builds/queries/refreshes; track counters (queries, build failures, embed errors); have the nightly maintenance scripts write a small status file (last run, items changed, failures) that `brain_status` reports. Make LLM-call failures in `ledger_update`/`moc_linker` set a non-zero exit / loud summary so a dead endpoint isn't logged as success. | Operator can see at a glance whether nightly maintenance actually did anything, distinguish "endpoint down" from "quiet night", and spot silent partial failures — none of which is visible today. | M | Adds a small status-file contract and log-format choices; keep it dependency-light (stdlib logging) to preserve the stdlib-only ethos of the maintenance scripts. |
| H10 | **Atomic, CRLF-preserving, backed-up note writes** | Make `complete_task`/`append_insight` write via temp-file + `os.replace`, preserve the file's original line endings (don't `splitlines()`/`"\n".join()` a CRLF file into LF), edit only the target line, and take a backup like the maintenance scripts do. | Stops single-task completions from rewriting every line ending on CRLF/LiveSync vaults (noisy diffs, sync conflicts) and prevents crash-mid-write truncation of hand-authored notes. | S–M | Line-ending detection adds a little logic; low risk. |

## Larger bets

| # | Title | What it is | Why it helps (user value) | Effort | Risk / trade-offs |
|---|-------|-----------|---------------------------|--------|-------------------|
| L1 | **Frontmatter/metadata-aware indexing & filtered search** | Parse YAML frontmatter (tags, type, topics, `moc:`, dates) into per-chunk metadata; let `brain_query` filter/boost by tag/type/folder/date-range and return that metadata with hits. | Moves from flat semantic search to "find decisions in *Projects/* tagged #delta from the last month" — the queries a real knowledge base needs. Leverages structure the MOC linker already writes. | L | Robust frontmatter parsing (multi-line/list YAML) is more than the current naive `split('---')`; adds query-API surface and a filter DSL to design. |
| L2 | **Smarter chunking (heading/structure-aware, real tokenizer)** | Replace the `words*1.3` heuristic and sentence-regex with a real tokenizer and Markdown-structure-aware splitting (respect headings, lists, code fences), carrying section context into each chunk. Fix/remove the broken `start/end` offsets. | Better-bounded, more coherent chunks improve retrieval precision and let results show "under heading X". Section-aware context makes snippets more useful to the agent. | L | A tokenizer dependency cuts against the lightweight ethos; chunk-format change forces a full reindex. Can be staged (structure-aware first, tokenizer later). |
| L3 | **Caching layer: in-memory index/metadata + embedding cache** | Cache the loaded FAISS index + parsed metadata in module state keyed by index mtime (reload only on swap); cache query embeddings (LRU) and per-chunk content-hash → embedding so unchanged chunks skip the endpoint. | Cuts per-query latency (no full re-read/JSON-parse of the whole corpus every search) and slashes nightly embed cost (only changed content is re-embedded). Compounds well with H3/H5. | M–L | Cache invalidation must be airtight against the atomic swap; an embedding cache adds a persistent store to manage. |
| L4 | **Proper packaging: `pyproject.toml`, pinned deps, console scripts** | Convert to an installable package with pinned/locked dependencies, `obsidian-brain` console entry points (index/search/serve/consolidate), and a documented `mcp>=1.26.0` floor. | Reproducible installs, no `sys.path.insert` hacks, easy `pipx`/container builds, version-pinned so a transitive bump can't break the nightly job. Foundation for everything else. | M | One-time migration; need to decide whether the stdlib-only maintenance scripts stay dependency-free (they should). |
| L5 | **Real test suite + CI** | Unit tests for chunking, dedup, frontmatter split, ledger JSON extraction (incl. reasoning-model template-shadow case), path-containment, atomic swap, and the task regex; fixtures with a tiny fake vault and a mocked embedding endpoint; run in CI. | Locks in every bug fix from the audit so they don't regress, and makes the larger bets (chunking, hybrid search, packaging) safe to attempt. Highest long-term leverage. | L | Up-front investment; needs a mock embedding server and FAISS-in-CI (CPU wheel is fine). |
| L6 | **Harden the LLM-driven maintenance (ledger/MOC) against bad model output & injection** | Fix `find_json_object` to prefer the *last* object with the expected keys (reasoning-model template shadowing currently no-ops the ledger); require completion `evidence` to be a verifiable substring of source-note text before checking an item off; fence/escape note bodies in prompts so a note can't forge a `### NOTE:` boundary or inject "mark item N done". | Stops silent no-op nights, prevents wrongly checking-off incomplete items, and closes a prompt-injection path on an unattended `--apply` process. Restores the "conservative & reversible" promise the ledger advertises. | M–L | Evidence-substring matching may reject some legitimate paraphrased completions (tune normalization); JSON-extraction change needs the reasoning-model test from L5. |
| L7 | **Per-build directory + retention/rollback for the index and note backups** | Keep the last N index builds and give the MOC/ledger note backups timestamped, path-namespaced filenames (today `{stem}.bak.md` collides across same-stem notes and is overwritten nightly). Add a one-command rollback. | Makes the system's "reversible by design" claim actually true: same-stem notes stop clobbering each other's only backup, and a bad nightly index/edit can be rolled back. Real disaster-recovery. | M | Retention adds disk usage and a pruning policy; rollback tooling is new surface to maintain. |
| L8 | **Multi-vault / namespaced brains** | Support multiple vaults/indexes selectable per request (or per server instance), with isolated `_brain/` and metadata namespaces. | Lets the same deployment serve a personal vault, a work vault, and a shared/team vault without cross-contamination — a natural growth path once auth (H6) exists. | L | Significant API and storage-layout change; only worth it if multi-vault is a real need. Defer behind H6/H7. |

---

### Suggested sequencing

1. **Land the cheap safety + honesty fixes first:** Q9 + H6 (security), Q4/Q8/H10 (resilience), Q5/Q6/Q7 (agent-facing correctness & honest docs). These are mostly S, high-leverage, and de-risk everything after.
2. **Then the retrieval-quality core:** H1 → H2 (with MMR) → L1/L2. This is where users feel the product get smarter.
3. **In parallel, the durability/ops spine:** H3 + H4 + H5 + H9, backed by L4 + L5 so the rest is safe to build on.
4. **Larger bets (L3, L6, L7, L8)** as appetite and need dictate — L6 specifically if the nightly ledger/MOC automation is relied upon, since it currently has silent-failure and injection exposure.
